为什么是 PicMint

该有的都有，不该传的一个字节都不传

大多数在线压缩工具会先把你的图片传到服务器。PicMint 反过来：所有计算都在这台设备上跑完。

零上传，零追踪

没有后端，没有图片接口，没有埋点。断网之后工坊照样能用 —— 这是最诚实的隐私承诺。

批量压缩

一次拖入整批图片，按质量或目标体积压缩。处理进度、前后体积、节省比例全部实时可见。

四格式互转

JPEG、PNG、WebP、AVIF 随需输出。编码器直接调用浏览器原生能力，不额外下载任何运行时。

智能缩放

只填最大边，另一侧自动等比推算。EXIF 方向自动校正，竖拍的照片不会横过来。

截图美化

渐变背景、圆角、内边距、柔和投影与水印，一次设置批量套用，适合做文档配图和社交封面。

一键打包 ZIP

处理完直接导出压缩包，文件名自动带上尺寸与格式后缀。ZIP 写入器只有 90 行，不引第三方库。

FAQ

你大概会想问

图片真的不会上传吗？我怎么验证？
打开浏览器开发者工具的 Network 面板，把 Studio 页面加载完之后再拖入图片 —— 除了页面本身，不会出现任何请求。 项目没有后端、没有第三方脚本、没有字体 CDN，部署在 GitHub Pages 上就是几个静态文件。
支持哪些格式？AVIF 呢？
输入支持浏览器能解码的所有格式（JPEG / PNG / WebP / AVIF / GIF 首帧）。 输出提供 JPEG、PNG、WebP、AVIF 四种。AVIF 编码依赖浏览器实现：Chrome 85+、Edge 121+、Safari 16.4+ 可用； 不支持的浏览器会自动隐藏该选项，而不是悄悄降级。
有文件大小或数量限制吗？
没有服务端，所以没有“上传上限”。真正的限制来自设备内存：建议单批不超过 128 张、单张不超过 80 MB。 超过这个量级时，Studio 会分批处理并给出进度，避免标签页卡死。
为什么有时候压缩后反而变大了？
常见于两种情况：一是原图已经高度优化过；二是把已经压过的 JPEG 转成 PNG（PNG 是无损格式）。 Studio 会为每张图显示实际体积，如果输出比输入大，会标出提示并保留原图供你选择。
可以商用吗？二次开发呢？
代码采用 MIT 协议，可以自由用于商业项目、闭源产品或二次分发，保留版权声明即可。 品牌名和 Logo 不在此授权范围内，衍生项目请换一个自己的名字。
